# Contributing

## Work unit

Every change starts with an Issue and ends with a reviewed Pull Request.

## Branches

Use `<type>/<issue>-<short-description>`.

Examples:

- `feature/12-create-work-order`
- `fix/31-idempotent-acceptance`
- `chore/1-project-governance`

## Commits

Use Conventional Commits and keep commits small and coherent.

Examples:

- `feat(work-orders): add work order entity`
- `test(dispatch): cover concurrent acceptance`
- `docs(adr): record messaging abstraction`

## Pull requests

A Pull Request must reference its Issue, explain decisions and show validation evidence. Prefer squash merge after review.

## Language

Code, identifiers, commits and repository documentation are written in English. Study explanations may be discussed in Portuguese.
